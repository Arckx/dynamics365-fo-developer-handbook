# Debugging Basics for Dynamics 365 Finance & Operations

This guide provides a **new‑developer friendly** introduction to debugging X++ code and diagnosing runtime issues in D365 FO.

---
## 1. Visual Studio Debugger

1. **Set a breakpoint** – open the X++ class or method, click the left margin or press **F9**.
2. **Attach to the AOS** – in Visual Studio, go to **Debug → Attach to Process**, select the **AOSService** process for your Tier‑1 VM.
3. **Run the code** – trigger the functionality (e.g., open a form, run a batch job) and the debugger will pause at the breakpoint.
4. **Inspect variables** – hover over a variable or use the **Locals** window. You can also add **Watch** expressions.
5. **Step through** – use **F10** (Step Over) or **F11** (Step Into) to walk line‑by‑line.

> **Tip:** For batch jobs, use the **`SysRunBaseBatch`** class and call `info("Debug start");` before the loop. Then attach the debugger and watch the batch execution.

---
## 2. Trace Parser (TraceParser.exe)

The Trace Parser is a lightweight tool that reads the **trace.log** generated by the AOS.

* **Enable tracing** – In LCS, go to **Environment → Diagnostics → Enable tracing** for the desired tier.
* **Download the trace** – After reproducing the issue, download the `trace.log` from the environment.
* **Open with TraceParser** – Filter by **Class**, **Method**, **Exception**, or **Duration** to locate hot spots.

### Common filters
| Filter | Example |
|--------|---------|
| `Exception` | `Exception=SqlException` |
| `Duration` | `Duration>5000` (ms) |
| `User` | `User=\_UserId=12345` |

---
## 3. Performance Profiler (PerfMon)

For performance‑related problems (slow forms, long‑running batches):

1. Open **Performance Profiler** from the **Dynamics 365** menu in Visual Studio.
2. Choose **Collect data** for **SQL**, **X++**, and **Cache**.
3. Run the scenario, then stop collection.
4. Review the **Hot Methods** and **SQL Queries** sections.

---
## 4. Common Debugging Scenarios

| Scenario | Recommended Tool |
|----------|------------------|
| **Null reference / `null` exception** | Visual Studio debugger – watch variable values before the line that throws. |
| **Deadlock or lock timeout** | Trace Parser – filter `Exception=DeadlockException`. |
| **Slow form load** | Performance Profiler – look for long‑running `select` statements. |
| **Batch job never finishes** | Attach debugger to the batch process or use `info()` statements to log progress. |

---
## 5. Debugging Checklist

1. **Reproduce** the issue in a Tier‑1 or Dev VM.
2. **Enable tracing** (if needed) and collect a trace log.
3. **Set breakpoints** at the suspected entry point.
4. **Attach the debugger** to the AOS process.
5. **Step through** and inspect variables.
6. **Use `info()`** statements for quick logging when breakpoints are not feasible.
7. **Analyze trace** with Trace Parser for hidden exceptions.
8. **Run Performance Profiler** for latency issues.
9. **Document** the root cause and fix in the **Anti‑Pattern** file.
